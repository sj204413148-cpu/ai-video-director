# AI Video Director · AI 视频总导演

一个面向 AI 编程助手的技能，将「一句话创意」拆解为可执行、可审核、可控成本的 AI 短片制作流程。

适合制作动画短片、剧情短视频、音乐短片，也支持只完成故事、分镜、提示词、审核或后期中的某个阶段。

> 这是指导 AI 助手工作的技能，不是独立的视频生成程序。仓库不包含模型、API 密钥、付费额度或现成的视频服务客户端。加载技能不会自动获得生图、视频生成或音视频感知能力。

## 核心流程

```text
需求与预算确认
  → 剧情完善与冷读审核
  → 分镜、构图、配色
  → 画风、角色与道具设定
  → 每镜首尾帧
  → 七段式视频提示词
  → 提交前审核、报价与费用批准
  → 视频生成与单镜修复
  → 拼接、转场、调色、放大、字幕与配乐
  → 全片复核与交付
```

核心原则：**能在文字里发现的错，不留到图上；能在图上发现的错，不留到视频上。**

- 故事确认前不生图，画风确认前不画正式镜头。
- 首尾帧与提示词审核通过后，仍需用户批准费用才能生成视频。
- 优先修剪、修复和单镜重拍，不无条件重做整片。
- 新版本另存，保留原图、原视频和失败记录。
- 不自动充值、不买额度；欠费或额度耗尽时保存进度。
- 抽帧检查不等于完整动态验收；无法试听时不声称已经检查声音。

## 安装

### Kimi Code：项目级安装

将整个技能文件夹放到目标工作区的 `.kimi/skills/` 中，保持如下路径：

```text
你的工作区/.kimi/skills/ai-video-director/SKILL.md
```

如果从本仓库克隆，在工作区目录执行：

```bash
git clone https://github.com/sj204413148-cpu/ai-video-director.git .kimi/skills/ai-video-director
```

目标文件夹必须不存在或为空。已有同名技能时先备份，不要直接覆盖。

重新开启会话后，检查技能列表是否包含 `ai-video-director`；具体发现与加载行为以所用客户端版本为准。

### 其他 AI 助手

仓库使用 `SKILL.md` 加按需加载参考文件的结构。可以按目标助手的技能安装规范放入对应目录，或让助手读取 `SKILL.md` 后按其流程工作。

不同助手的工具、权限、子 agent 和技能发现机制不同，本仓库不保证未经适配即可使用其全部能力。

## 使用示例

### 从创意开始

```text
使用 ai-video-director 技能，帮我制作一个 30 秒、9:16 的 AI 动画短片。
创意：一只总迟到的小猫，想尽办法在日落前送出一封信。
预算上限：30 元。
先讨论故事，未经我确认不要生图，也不要调用付费接口。
```

### 只做分镜和提示词

```text
使用 ai-video-director，把下面的故事整理成分镜表、配色方案、首尾帧计划，
以及每镜七段式视频提示词。本次不生成图片或视频。
故事：[粘贴内容]
```

### 审核已有素材

```text
使用 ai-video-director，只读审核这个镜头，不修改文件，也不提交生成。
材料：[分镜、首尾帧、角色设定、配色规则、视频提示词的实际路径]
请指出问题和证据，最后说明通过、不通过或材料不足。
```

### 继续已有项目

```text
使用 ai-video-director，继续 video-projects/cat-letter/ 项目。
先读取项目状态、需求、决定和费用记录，汇报未完成阶段，不重做已批准资产。
未经我批准不要产生新的费用。
```

## 工具与服务要求

| 阶段 | 所需能力 |
| --- | --- |
| 故事、分镜、提示词 | 文本推理与项目文件读写 |
| 构图、图片审核 | 实际图像读取与视觉检查能力 |
| 设定图、首尾帧 | 可用的生图或图片编辑工具 |
| 视频生成 | 已接入、已授权的视频生成服务，如支持所需输入方式的 Seedance 服务 |
| 后期与技术校验 | ffmpeg、ffprobe，以及可用的脚本运行时 |
| 动态、声音验收 | 具备实际音视频感知能力的工具，或人工播放验收 |

Codex 可作为画师，前提是当前环境确实提供生图能力；仅安装 CLI 并不代表可以生图。缺少生成工具时，可以先完成故事、分镜和提示词，不应伪造生成结果。

模型 ID、价格、支持的分辨率、时长、首尾帧能力和 API 参数，必须在实际调用前核对官方文档与账号权限。文章中的历史示例不作为永久有效的配置。

API 密钥由用户在服务支持的安全方式下配置，例如环境变量。不要把密钥提交到仓库、写入提示词或打印到日志。

## 七段式视频提示词

每个镜头包含以下七部分：

1. **画风**：线条、材质、光照等，与已批准设定一致。
2. **镜头**：时长、景别、机位、运镜及其动机。
3. **构图与配色**：人物位置、背景、主辅色与光向。
4. **人物**：角色、服饰、固定特征、道具与数量。
5. **逐秒**：动作先后、因果、路径、画面左右及结束状态。
6. **声音**：对白、音乐与有明确原因的音效。
7. **约束**：允许出现的对象、一致性要求及后期字幕分工。

完整模板见 [prompt-library.md](references/prompt-library.md)。逐秒描述只是生成指导，不保证模型严格按秒执行，需预留剪辑余量。

## 可选四角色协作

- **主做**：负责制作、项目管理与版本。
- **审核**：只读挑错，不直接修改制作文件。
- **监督**：逐项核对用户明确提出的要求。
- **代理**：仅在用户明确授权的范围和金额内代决。

技能不会默认启动子 agent，也不会让代理自行批准付费任务。没有独立 agent 时，单助手复核必须明确标注，不冒充独立冷读审核。

## 产物与费用记录

技能指导每支短片使用独立项目目录，保存：

- 项目目标、需求、批准记录与待确认事项。
- 故事、分镜表、色板、风格与设定资产。
- 分版本的首尾帧、提示词、视频片段与后期产物。
- 审核报告、生成任务 ID、预计上限、实际费用及预算保留额。
- 成片技术指标、验收状态、未解决问题和制作经验。

模板见 [project-templates.md](references/project-templates.md)。请求超时后先查已保存的任务状态，避免重复提交与重复扣费；失败任务也可能计费。

## 限制与发布注意事项

- 这是流程技能，不承诺某种模型的出片质量、费用或生成成功率。
- 技术解码检查、视觉抽帧检查、动态与声音验收是不同的检查，不能互相代替。
- 色彩转换依据素材实际参数，不把所有视频统一当作某个色彩矩阵处理。
- 音乐、肖像、商标与参考素材需要相应使用权；不能因为标注来源就认为取得了授权。
- 上传、公开发布以及超出批准范围的费用，需要另行取得用户授权。
